====================================================================
ANÁLISIS DE RENDIMIENTO Y COMPARATIVA: BOOTSTRAP vs TAILWIND CSS
====================================================================

1. MEDICIÓNDE RECURSOS EN DEVTOLS (NETWORK)
--------------------------------------------------------------------
* Bootstrap v5.3 (Carga en Sitio v2.0):
  - CSS (`bootstrap.min.css` CDN): ~165 KB
  - JS (`bootstrap.bundle.min.js` CDN): ~80 KB
  - Peso total transferido: ~245 KB

* Tailwind CSS v3.4 (Campaña Nocturna minificada):
  - CSS (`output.css` compilado y minificado): ~14.8 KB
  - JS: 0 KB (No requiere JavaScript para layout ni utilidades responsive)
  - Reducción del peso total: ~94% de ahorro en transferencia de red.

--------------------------------------------------------------------
2. COMPARATIVA DE FRAMEWORKS SEGÚN 4 CRITERIOS
--------------------------------------------------------------------
| Criterio | Bootstrap v5 | Tailwind CSS v3 |
| :--- | :--- | :--- |
| Curva de aprendizaje | Rápida e intuitiva. Ideal para prototipos usando componentes ya listos (`.navbar`, `.card`, `.btn`). | Moderada al inicio por la cantidad de utilidades de atómicos, pero sumamente ágil al dominar la sintaxis. |
| Personalización | Compleja. Requiere sobrescribir variables Sass/CSS o usar `!important` para adaptar colores corporativos específicos. | Total y nativa. La paleta de marca y tipografías se definen directamente en la configuración sin generar código redundante. |
| Tamaño final del CSS | Fijo y pesado. Carga cientos de componentes no utilizados por defecto (~245 KB en total). | Ultraligero. Purga automáticamente cualquier selector no usado en el HTML, reduciendo el compilado a ~14.8 KB. |
| Casos de uso ideales | Paneles administrativos internos (Dashboards), herramientas de prototipado rápido o sitios web convencionales. | Landing pages de alto tráfico, interfaces de usuario personalizadas, sitios enfocados en rendimiento y mobile-first. |

--------------------------------------------------------------------
3. RECOMENDACIÓN TÉCNICA JUSTIFICADA PARA RUEDA LIBRE
--------------------------------------------------------------------
Recomendamos adoptar Tailwind CSS como el framework estándar para las futuras versiones del sitio completo de Rueda Libre por las siguientes razones clave:

1. Optimización para tráfico móvil (Redes Sociales): 
   Con una reducción del 94% en el peso del recurso y 0 KB de JavaScript bloqueante, la landing carga instantáneamente incluso en redes móviles 3G/4G con cobertura limitada.
2. Identidad Visual 100% fiel: 
   Permite integrar con precisión milimétrica la paleta corporativa (Verde Ruta, Naranja Pedal, Azul Noche, Crema y el nuevo Amarillo Farol) y el modo oscuro sin sobrecargar el código.
3. Mantenibilidad y Limpieza: 
   Mediante la estrategia de componentes del kit y el uso controlado de `@apply` en `src/input.css` para elementos altamente repetitivos (como botones), logramos un HTML limpio y fácil de mantener por el equipo de desarrollo.

   REGISTRO DE VERIFICACIÓN DE TAILWIND CSS 

Clase en uso (ej. `bg-amber-400`):
   - Encontrada en `src/output.css`: SÍ.
   - Detalle: Se generó la regla CSS `.bg-amber-400 { --tw-bg-opacity: 1; background-color: rgb(251 191 36 / var(--tw-bg-opacity)); }`.

Clase NO usada (ej. `bg-pink-500`):
   - Encontrada en `src/output.css`: NO.

¿Por qué ocurre esto?
   Ocurre porque el motor JIT (Just-in-Time) de Tailwind CLI escanea los archivos declarados en `tailwind.config.js` y solo compila en `output.css` las clases que detecta en el HTML. De esta forma ignora todo el CSS innecesario (como `bg-pink-500`) para que la página sea liviana.
